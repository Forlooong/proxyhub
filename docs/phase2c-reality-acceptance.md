# 阶段 2c：REALITY 目标与 SNI 迁移验收

日期：2026-10-15（Asia/Shanghai）。版本：`0.5.0a1`。沿用专用 Debian 12 amd64 VPS、sing-box 1.14.3、Mihomo 1.19.32、Nginx 1.30.5 和 Node 24.21.0。本增量遵循重对齐总方案第 5.2、10.2 节；完整阶段 2 与首版发行仍未完成。

## 交付

REALITY 目标、入口与当前发布入口分别具有稳定引用。迁移创建独立入口并更新订阅，原入口继续运行；切回保留入口、显式退役各自生成计划。当前发布入口和最后一个入口不能退役，没有自动到期退役。全部入口沿用原节点身份及密钥，`server.site_domain` 继续表示原网站；原命令及默认网站行为保留。

本机目标引用已启用网站、绑定域名、内部 TLS 监听和证书。外部目标仅接受 DNS 名称和 HTTPS 443，检查全部解析地址，拒绝非公网、本机、回环及重绑定；固定已检查 IP，并验证 TLS 1.3、X25519、信任链及 SNI 名称，不抓取外部正文。最多保留 8 个独立入口。网站、域名和证书依赖保护覆盖全部保留入口。

每个新入口使用独立 sing-box 实例，原核心进程不重载。Nginx 和订阅发布器重载完成路由、订阅切换；提交前实际穿过公共 SNI 路由验证将要发布的入口。本机目标还核对所选证书指纹与网站正文。未修改的旧外部目标不会成为切回、恢复或普通订阅发布的新网络依赖；保留入口不代表承诺第三方一直可用。

独立实例选择依据锁定版本的 [sing-box REALITY 服务端](https://github.com/SagerNet/sing-box/blob/v1.14.3/common/tls/reality_server.go)、[sing-box 运行命令](https://github.com/SagerNet/sing-box/blob/v1.14.3/cmd/sing-box/cmd_run.go)与 [Mihomo 使用的 REALITY 客户端实现](https://github.com/MetaCubeX/utls/blob/v1.8.7/reality.go)，没有套用其他核心的多目标配置格式。CLI 与面板操作见[面板手册](panel.md)。

## 验收结果

| 检查 | 结果 |
| --- | --- |
| Linux 相关测试 | 目标、迁移激活、网站依赖、管理操作、CLI、部署/恢复及订阅激活共 377 项通过，另有 125 项 subtests 通过。首次 376 passed、1 failed；旧 CLI 测试的路径解析意外跟随测试 VPS 的真实 current 链接，修正 fixture 隔离后仅补跑该项，1 passed；产品实现未因此修改 |
| 外部目标与恢复边界 | 针对性回归覆盖旧外部目标失效后切回、普通订阅发布不探测目标、旧运行时证书过期后修复证书；没有通过停止第三方网站制造公网故障 |
| 前端 | TypeScript 检查、Vite 构建通过。专用 Edge 测试会话完成本机迁移、切回保留入口、显式退役临时外部入口；390px 与 1440px 无横向溢出，功能流程控制台 0 errors / 0 warnings。最终升级重启管理服务后，旧内存会话按预期返回一次 401；重新登录后完成最新摘要预览、取消及注销 |
| 本机目标迁移 | 从原网站迁移到已有第二网站的绑定域名，使用新内部入口。新旧公共 SNI 路由、各网站实际证书与正文均通过；订阅发布新 SNI |
| 外部目标迁移 | CLI 准备外部 HTTPS 目标计划并显式应用，旧入口与本机新入口同时保留。外部 TLS 校验和实际代理请求通过，随后从面板切回本机入口 |
| 真实客户端 | 使用锁定 Mihomo 分别通过原 SNI、本机新 SNI、外部 SNI 完成真实公网代理请求。最后重新下载当前订阅，GET/HEAD 元数据一致、未知令牌拒绝、覆盖配置保留，导入与真实请求通过 |
| 既有连接保留 | 在升级和迁移前建立经原 REALITY 入口的 CONNECT 长连接，连接到测试 VPS 的临时回显服务；同一连接跨越失败回退、本机/外部迁移、切回、显式退役与中断恢复后仍可收发。不是仅根据 PID 推断连接保留 |
| 激活失败回退 | 新候选的公共 SNI 实际加载且健康验证通过后注入失败；旧路由、发布及实例恢复，revision 不提交、计划标记 failed、journal 无待恢复项 |
| 真实进程中断恢复 | 在写入 activating journal、切换 current 链接和发布磁盘文件后，独立激活进程执行 `os._exit(86)`；恢复旧状态成功，revision 不提交、journal 清理，再次恢复返回无待恢复项 |
| 无效目标 | 私有/本机解析、公网入口自回环、外部证书名称不匹配、本机未绑定 SNI 均在切换前拒绝。地址范围、监听冲突与候选不可变性另有针对性测试 |
| 依赖与退役 | 真实接口拒绝停用引用网站、解绑引用 SNI、删除引用证书和退役当前主入口。临时外部入口单独退役后，新客户端使用该 SNI 被拒绝，原入口长连接及本机主入口仍正常 |
| 配置和服务保留 | 服务器、网站、订阅元数据及客户端覆盖配置的摘要与迁移前基线相同；proxy/nginx/publisher 主 PID 全程相同。仅为升级应用重启管理服务和面板，没有修改 SSH、防火墙或原命令 |
| 部署一致性 | 最终 282 个应用、前端、生成器及锁定运行时文件的 SHA-256 与部署包逐项一致，属主及不可组/其他用户写入权限通过；原五项常驻服务均为 active，新本机入口单独运行 |
| 独立审查 | 已修复并复核远端故障阻断切回、订阅发布耦合目标探测、旧过期证书阻断修复的问题；最终只读复核未发现剩余阻断 |

Windows 上部分真实 OpenSSL 和 POSIX 权限检查受宿主沙箱限制，对应检查已在 Linux 上通过，没有放宽路径或权限校验。上述数量描述各次检查，不相加推算覆盖率。每次操作按其变更范围验证，本次 VPS 验收另行覆盖全部保留的新旧路径。

最终保留原入口和本机新入口，订阅使用本机新 SNI；临时外部入口已退役。原网站、第二网站、证书、凭据和历史均保留，没有强制续期证书。验收客户端、临时回显服务、源码测试副本及任务日志清理，保留一份升级前应用备份。私钥不离开服务器，公开记录不保存部署身份、真实域名、凭据或订阅链接。
