# 阶段 2b：多站点与证书依赖

依据重对齐总方案第 10.2 节，只完成多站点及证书绑定管理。保留既有 REALITY 的 SNI、内部目标、凭据、订阅和阶段 2a 内容历史；目标迁移、HY2、规则与计量不进入本增量。

## 实现

- 在现有版本化配置中保存网站、证书绑定和独立监听身份；旧配置归一化为固定默认资源，直到已校验候选应用才写入新版本。不增加资源数据库。
- 默认网站继续使用 `site/`，新增网站使用按稳定 ID 隔离的内容树；内容历史按网站过滤，不能跨站恢复。证书绑定 ID 独立于不可变 PEM 版本，消费者引用绑定 ID。
- 新站点域名经原 Nginx SNI 入口直达其专属内部 TLS 监听，原网站域名仍经 REALITY。创建、选择、启停、删除、域名绑定/解绑、证书绑定与消费者列表均提供 CLI/面板入口。
- 域名、SNI 和监听冲突在应用前检查；新增监听不接管已有服务端口。默认网站和原 SNI 受到 REALITY 依赖保护，已引用证书不可删除。
- 复用计划、revision、journal 和恢复。网站及证书操作以受约束的 Web 激活重载 Nginx 和发布器，保留代理进程；不允许借此修改节点或订阅设置。逐个验证所有启用网站与订阅消费者的实际证书指纹和网站内容，失败恢复旧版本。
- 原 ACME lineage 保留；新增证书使用独立 lineage，导入证书按实际来源标记。新证书申请和续期依旧先预览、显式应用，不在普通预览中签发证书或泄露私钥。
