# 阶段 2 其余协议门槛

依据重对齐总方案第 6、10.2 节与本次明确授权，依次补齐 Shadowsocks AEAD/2022、Trojan、TUIC v5、AnyTLS、VMess、SOCKS5，以及 VLESS 的其余选定传输。保留已有 REALITY/HY2、网站、订阅元数据、覆盖、命令和历史；不实施外部 URI 导入、多订阅、规则或计量。

- 使用一个严格的受管节点列表，节点具有稳定编号、独立监听和随机凭据。创建、更新、启用、停用、删除复用计划和 revision；更新不更换凭据，删除须先停用。按协议检查 TCP/UDP 端口、名称、证书、REALITY 目标依赖，普通配置不可绕过操作。
- 每个节点使用独立低权限 sing-box 实例，选择已有入口之外的 IPv4 公网端口；不修改 443 路由。证书材料沿用受保护的运行配置，归档权限不放宽。只操作变更节点和发布器；证书更换只重启材料变化的消费者，失败或中断恢复旧服务、发布和状态。
- 唯一转换器追加启用节点，保留 REALITY/HY2 顺序和用户覆盖；同步输出 Mihomo YAML、原始 URI 与协议格式边界。严格拒绝不兼容选项，不能把格式检查视为真实代理验证。
- 固定 Mihomo 1.19.32 的 Trojan 没有 H2 分支，H2 会落到 TCP；因此拒绝该组合并记录源码依据。VLESS REALITY 只接受 TCP/H2，Vision 只接受 TCP。HTTPUpgrade 明确表达升级语义；VMess HTTP/1 仅使用 security none。其他限制以实际源码与端到端验收为准。
- CLI 和面板提供同等生命周期、协议/传输选择与证书依赖，普通预览不显示凭据。明文传输与无认证 SOCKS5 的影响必须可见，默认 SOCKS5 使用认证。
- 专用 VPS 逐项验收实际 TCP 与适用的应用 UDP、生命周期、证书新指纹和坏证书回退、冲突及进程中断恢复。迁移前保持旧 REALITY/HY2 长连接并核对原配置和进程；升级发布器代码所需的单次重启单独记录。没有公网 IPv6 时明确未验证，不声称通过。
- Direct 是独立转发功能，来源仅用于旧部署迁移；本项目不接管旧部署，不将 direct 出站当成已交付节点或扩展本次范围。指定 GUI 和发行资源矩阵仍分别记录。

验收中补充的明确边界：锁定 Mihomo 的 H2 UDP 未通过，YAML 不声明支持；含 `udp:false` 节点的默认 rule 尾部拒绝，避免核心跳过规则后 DIRECT。TUIC 明确协商 h3，TCP 预检容许已停止连接的 TIME_WAIT 且仍拒绝活动监听。以上均由真实失败与对照实验推动，不引入规则策略流水线或升级锁定核心。证据见[协议收口验收](../../phase2-protocols-acceptance.md)。
