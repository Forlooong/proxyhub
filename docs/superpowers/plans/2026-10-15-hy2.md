# 阶段 2d：HY2 与协议能力矩阵

依据已批准总方案第 5、10.2 节推进，复用已有计划、revision、证书绑定与恢复机制。保留新旧 REALITY 入口、网站、订阅元数据、客户端覆盖和原命令；不实施多订阅、规则、计量或通用 Host 初始化。

- 可选单个 HY2 资源具有固定节点/监听身份、独立随机凭据、名称、UDP 端口、SNI、证书引用和启停状态。创建、更新、启用、停用均显式预览/应用；普通部署、Web 或订阅操作不可绕过类型化变更。停用保留资源、凭据和证书依赖。
- 独立 sing-box 服务监听 IPv4 UDP（默认 443），与既有 TCP 入口共存，不开启网站 HTTP/3，不重启 REALITY。HY2 更新/停用会影响其自身连接，预览明确说明；高级混淆、端口跳跃及带宽参数不提前加入。
- 唯一转换器追加启用的 HY2 到 Mihomo 与原始订阅；原 REALITY 顺序优先，用户覆盖与元数据保持。严格拒绝未知字段及不兼容协议参数。
- 准备与应用检查证书 SAN、材料摘要、候选不可变性和新增 UDP 端口占用。激活只操作 HY2 与发布器；Web 证书变更按材料变化更新 HY2，验证实际 QUIC 证书指纹和认证代理路径后才提交。失败及进程中断恢复上一资源、服务与发布状态。
- CLI 与面板接入同一操作层，普通预览不显示 HY2 密码。证书消费者、服务状态与依赖图反映真实资源，不能以运行状态替代客户端验收。
- 专用 VPS 验证 TCP/UDP 共存、REALITY/HY2 真请求、原长连接保留、证书切换/失败恢复、停用/启用、端口冲突及进程中断恢复。按本机实际网络分别记录 IPv4/IPv6，不把没有公网 IPv6 的测试机标成 IPv6 通过。
- 对原项目已声明的新建协议逐项记录已实现、待实现或不支持；矩阵存在不代表所有协议已交付，也不提前宣称完整阶段 2 或首版完成。
